# 五次假绿的教训

这条路线经历过五次"门禁全绿、实则错误"的事故,每一处都留下了一个探针脚本:

1. **浮点结合律**:`(增益×包络)×信号` 与 `增益×(包络×信号)` 在实数里相等,
   在 float64 里差一个 ULP,经 float32 落盘后内容哈希漂移——而打印出来的
   最大差值是 0.000000。
2. **从未跑过的路线**:某条路线从未用自己的 CLI 跑过,双十六进制解析的 bug
   一直活着。
3. **用信号迁就阈值**:门禁首次变红时改的是信号而不是阈值——校准的方向反了。
4. **NaN 下的全绿**:空层配置让整条链在 NaN 里静默通过所有门。
5. **PIL 与 NumPy 不共享内存**:在 PIL 图上画的皴笔从未写回 NumPy 数组,
   五分之四的笔触被无声丢弃。

结论只有一句话:**门禁验证的是它碰巧计算的东西,不是它声称验证的东西。**
所以每个门都必须配一个"被看着变红"的突变体,连门禁自己也要接受审计。
