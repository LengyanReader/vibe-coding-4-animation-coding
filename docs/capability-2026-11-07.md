# 能力水平评估 — 2026-11-07(13 条路线 × 可证性分级)

> 分级框架沿用 `docs/styles.md` §0.1(2026-11-05 建立,以**可证性**而非风格分类):
> **甲** = 已验证的属性就是成功属性(机器门禁即完整验收);
> **乙** = 物理可测、工艺仍需人眼(门禁真实但不是全部真相);
> **丙** = 语法可控、执行天花板可见(门禁全绿也可能被眼睛否掉——illustration/manga 的教训);
> **丁** = 结构性不可达(原创角色设计、多格一致性、电影级 3D、版权角色、扩散模型)。
> 冲突裁决与教训记录见 `docs/audit-2026-11-05.md` §F(五个实测假绿 + 探针脚本)。

## 2. 音频能力阶梯(现状)与提升队列

**现状(全部确定性):**

| 层 | 内容 |
|---|---|
| 引擎 ×2 | `additive`(零装,谐波和)与 `fluidsynth`(FluidR3_GM 采样,repo-tool 哈希锁)同吃一份事件契约 |
| 作曲器 ×2 | `chord_events`(小调 pad+arp)/ `piano_events`(Kern 式 8 小节全手写谱,种子不参与作曲) |
| 音色 ×6 | sine/pad/marimba/bass-synth/arp/felt-piano(逐次谐波指数衰减包络) |
| 空间/母带 | 双去相关单声道→立体声;NumPy 卷积混响(IR 种子恒定);R128 两遍母带,LUFS 实测复验 |
| 导出 | 手写 SMF(write_midi,零依赖) |
| 门禁 | 9 项验收 + 双渲染确定性;golden `b5bf04fd…`;sf2 sha256 入 manifest |

**缺口(如实):** 单 program 单轨(无多音色编排);力度=线性 gain 映射(无 CC1/CC11 表情);单速度事件(无 rubato/渐快);无乐谱导出(music21/LilyPond 未装);无 stems/SFX/自适应音乐;作曲器硬编码 8 小节(bars>8 无旋律);真峰/ LerA 未测。

**提升队列(按性价比,前四项零安装):**

1. **多轨多 program**——`write_midi` 按事件 `channel/program` 分轨 → 钢琴+弦乐垫+拨弦的编排出可能;加"track program exactly N"门。
2. **力度与表情包络**——事件级 velocity 曲线 + CC11 表情轨 → 分句呼吸;门:力度范围与乐句轮廓可测。
3. **速度曲线(rubato/accel.)**——多 tempo 事件或每小节 tempo map → 演奏感;门:拍格网格实测对齐。
4. **SFX 合成器**——噪声爆发/扫频/撞击(供游戏消费,连上 games 队列);门:时长/频谱能量/峰值。
5. **乐谱导出**(轻装,需同意):music21 → LilyPond → PDF/PNG 可读谱面——"符号层成为可检视的产物"。
6. **测量补全**:真峰(inter-sample)与 LRA 门,补齐交付级响度语义。

## 3. 乙→甲的通用升级模式

ink/anime/image 的共同升级路径是:**把人眼正在充当的"验收器"逐个替换成仪器**。
ink 已示范:墨色五阶(直方图门)、留白(比例门)、雾(区域亮度门)、印(连通域门)。
剩下的"笔性"(皴法密度随坡度、勾线抖动谱、构图重心与气口)按同一模式逐个形式化;
每替换一个,就该有个探针脚本证明旧门为什么不够(styles.md §0.1 的五个假绿探针即范例)。
